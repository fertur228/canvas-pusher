# FlyMind — Phase 1 Neural Engine PoC

Этот документ фиксирует исходный PoC. Продолжение исследования GF и отдельные
литературные профили описаны в [валидации escape circuit](neural-escape-validation.md).

Реализовано в локальной ветке `feat/flymind-neural-poc`. До начала работы Git был
чистым. Изменения не отправлены на сервер, ресурсы не развёрнуты. Производственные
`src/main.py`, `src/core/`, `src/setup_db.py`, `requirements.txt`, SQL, GitHub Actions
и Supabase/Telegram webhook не изменены.

## Файлы и baseline

- `src/neural/`: `models.py` — представления и параметры; `ingest.py` — извлечение;
  `loader.py` — проверка данных; `audit.py` — сверка с источником; `engine.py` — Brian2;
  `experiment.py` — CLI и JSON; `benchmark.py` — измерения в отдельных процессах.
- `data/neural/flywire_v783/{neurons.csv,connections.csv,manifest.json}` — реальные
  данные фрагмента, примерно 1,35 МиБ суммарно. `data/neural/.gitignore` исключает
  исходный cache и результаты запусков из Git.
- `requirements-neural.txt` — отдельные зависимости Python 3.11/3.12.
- `tests/neural/` — нейронные тесты; `tests/test_scanner.py` обновлён под существующий
  `AsyncCanvasScanner`, без изменения самого сканера.
- `docs/neural-benchmark.json` — измерения и среда; этот документ — воспроизведение,
  источники, ограничения и отчёт.

Исходный `python -m pytest -q`: ошибка collection, поскольку `test_scanner.py`
импортировал удалённый `CanvasScanner`. Остальные исходные тесты: **11 passed**.
Первоначально системный Python 3.14 вообще не имел pytest. После установки зависимостей
ошибка старого теста подтверждена; среда нейронного PoC отдельно создана на Python 3.11.
Установленный Brian2 2.9.0 не работал с Python 3.14/NumPy 2.5.4; рабочая комбинация
закреплена как Python 3.11 и NumPy 1.26.4.

Рассмотрена существующая архитектура: Python сканирует Canvas, считает diff/GPA и
пишет `canvas_state`, `course_grades`, `health_checks` в Supabase. Действующий workflow
запускает `src/main.py` каждые пять минут; Deno webhook обслуживает Telegram и инициирует
GitHub workflow. Ни импортов этих компонентов, ни сетевых вызовов к ним в PoC нет.

## Реальные данные и происхождение

Используется **FlyWire FAFB, materialization v783**, мозг взрослой самки
**Drosophila melanogaster**, а не личинки и не MaleCNS.
[Dorkenwald et al., Nature 2024](https://doi.org/10.1038/s41586-024-07558-y)
описывает этот коннектом; [официальный архив](https://doi.org/10.5281/zenodo.10676866)
документирует поля связности, подсчёт синапсов и предсказания медиаторов.

Фактический источник связей — публичные gzipped CSV Princeton:

- [connections.csv.gz](https://storage.googleapis.com/flywire-data/codex/data/fafb/783/connections.csv.gz),
  50 289 304 байта, **3 869 878 строк neuron–neuron–neuropil** в исходном файле.
- [neurons.csv.gz](https://storage.googleapis.com/flywire-data/codex/data/fafb/783/neurons.csv.gz)
  — каталог root IDs и предсказания нейромедиаторов.
- Аннотации [flyconnectome/flywire_annotations v2.1.0](https://github.com/flyconnectome/flywire_annotations/tree/ebd66db2596fcc39c6950fb54ea3efa00f7fe8a0),
  commit `ebd66db2596fcc39c6950fb54ea3efa00f7fe8a0`:
  `Supplemental_file1_neuron_annotations.tsv`.
  [Schlegel et al., Nature 2024](https://doi.org/10.1038/s41586-024-07686-5).

URL этих CSV взят из [официального загрузчика Codex](https://github.com/murthylab/codex/blob/3477b6cfccaf3bf976e6af0d40513ad221311a36/codex/data/local_data_loader.py).
Это конкретные закреплённые файлы v783; новые аннотации текущего Codex могут отличаться.
SHA-256 всех источников, извлечённых CSV и алгоритм выбора находятся в `manifest.json`.
Загрузчик прекращает работу при изменении источника или checksum; токены не нужны.
Полный многогигабайтный массив синапсов не скачивался.

Лицензия публичных данных FlyWire: **CC BY-NC 4.0**, согласно
[официальным правилам](https://join.flywire.ai/guidelines). Требуются атрибуция и
некоммерческое использование; коммерческое применение этих данных потребует отдельного
разрешения. Эта лицензия относится к данным, а не устанавливает лицензию всему репозиторию.

Выбор: все 104 **LC4**, 210 **LPLC2** и две **DNp01 / Giant Fiber**; реальные пути
между ними в графе связей с этими клетками; затем сильнейшие непосредственные партнёры
по сумме синапсов. BFS и равные веса разрешаются числовым порядком root ID.
Остальные клетки — их окружение, а не утверждение, что все 1 500 клеток специфичны для
реакции бегства. Среди партнёров есть аннотированные TmY3, Tm5Y, T2 и LPLC4;
82 клетки оставлены без типа, вместо выдуманной аннотации.

**Итог: 1 500 нейронов, 25 206 строк связности, 17 186 направленных пар,
276 399 синапсов, одна слабосвязная компонента.** Одна пара может иметь строки
в нескольких neuropils. Исходный файл Codex уже фильтрован; PoC не вводит дополнительный
порог и сохраняет каждую его строку внутри выбранных IDs, включая самосвязи,
направления, neuropil, `syn_count`, `nt_type`. За пределами выбранного набора связи
отсечены; отсутствующие связи не восстанавливаются.

Giant Fiber IDs: `720575940622838154`, `720575940632499757`. Для обеих клеток
проверены реальные входы LC4 и LPLC2. Все root IDs хранятся строками, включая JSON,
чтобы JavaScript не терял точность uint64.

[Ache et al., Current Biology 2019](https://doi.org/10.1016/j.cub.2019.01.079)
экспериментально связывает LC4 с компонентом угловой скорости, LPLC2 — с размером
приближающегося объекта, а их входы сходятся на GF. Это обосновывает выбор схемы,
но не валидирует параметры и результаты нашего PoC. FAFB не содержит нижележащие
цепи вентральной нервной цепочки и мышцы; связи GF с мотонейронами и электрические
синапсы здесь не симулируются.

## Динамика и допущения

Brian2 2.9.0, NumPy backend, без компиляции: однокомпартментные leaky integrate-and-fire
нейроны, точное обновление линейного уравнения между событиями:

```text
dv/dt = (Vrest - v + drive) / tau
при v >= Vthreshold: spike; v = Vreset; refractory
при входящем spike через delay: v += syn_count * mV_per_synapse * sign
```

Фиксированные **допущения**, не измерения в выбранных клетках:

- `tau=20 ms`, rest/reset `-65 mV`, threshold `-50 mV`.
- Refractory `2 ms`, одинаковая задержка `1 ms`, шаг `0.1 ms`.
- `0.02 mV` на аннотированный синапс; без нормализации, обучения или пластичности.
- Предсказанный ACh даёт возбуждение, GABA — торможение. GLU, DA, SER, OCT и UNKNOWN
  имеют нулевой эффект: рецепторы и влияние модуляторов не установлены для этих пар.
  Структурно все строки остаются в сети. Итог: 14 417 возбуждающих,
  7 692 тормозных и 3 097 строк с нулевым эффектом.
- Все клетки начинают в rest; случайности нет. Прямой прямоугольный drive `30 mV`
  подаётся на LC4/LPLC2 с 20 до 80 ms. Это токовая стимуляция визуальных проекционных
  нейронов в упрощённой модели, не симуляция сетчатки или настоящего looming-стимула.
- Во время refractory потенциал фиксирован; входящие события не меняют его.

Полярность медиаторов — отдельное предположение. Пример использования LIF в этой
области — [Shiu et al., Nature 2024](https://doi.org/10.1038/s41586-024-07763-9),
однако наш код не воспроизводит и не наследует валидацию той модели. Предсказания
медиаторов в FlyWire получены внешним опубликованным классификатором; сам PoC
не обучает модель, не вызывает LLM или AI API.

За 200 ms получены **988 спайков у 340 клеток**. Обе GF **без спайков** при этих
параметрах. Значения мембранного потенциала конечны; при семплировании через 1 ms
диапазон `-69.2314 .. -50.0076 mV`. Это инженерный результат выбранной модели,
не подтверждение биологической реакции или автономного поведения.

JSON/JSON.gz содержит абсолютное время создания UTC, относительное время спайков
в ms, IDs и параметры, активности всех клеток, GF readout, выбранные voltage traces,
финальные потенциалы, источники и среду. Отдельный `.summary.json` содержит CPU,
wall time и RSS. `activity_sha256` считается по нейронным результатам и параметрам:
время экспорта и длительность выполнения исключены. Сжатые файлы целиком могут
различаться из-за времени создания; нейронная активность совпадает.

## Проверки и измерения

**49 passed, 84 warnings, 5.83 s**, Python 3.11.17. Warnings — deprecated вызовы
pyparsing внутри Brian2. Проверены IDs/точность, endpoints, дубликаты, checksum,
реальные LC4/LPLC2 → GF, знаки и задержки, аналитическое время достижения порога,
refractory, конечность потенциалов, повторяемость, отсутствие спайков без стимула,
экспорт без сетевого доступа и защита существующих результатов от перезаписи.
Аудит источника проверил все IDs, аннотации и полное совпадение индуцированного графа.
Повторное извлечение дало одинаковые SHA-256 обоих CSV и manifest.

С cache исходников этот аудит входит в 49 тестов; без него один тест audit
явно пропускается, остальные тесты работают с включённым реальным фрагментом офлайн.
Только небольшие фикстуры для математики/валидации синтетические и явно помечены.

Измерения в `neural-benchmark.json`: macOS 26.5.1 ARM64, 11 логических CPU,
Python 3.11.17, три отдельных процесса со стимулом плюс контроль. Численные библиотеки
ограничены одним потоком; файловый cache ОС уже прогрет. Включены чтение/проверка
данных, импорт Brian2, симуляция и экспорт, без установки зависимостей и скачивания.

- Медиана CPU: **0.730246 s**; wall time всего дочернего процесса: **0.952186 s**.
- Максимальный process lifetime peak RSS: **136.34375 МиБ**, high-water mark ОС.
  Дополнительно RSS семплируется каждые 5 ms; на Windows доступен только sampled peak.
- Все три запуска имеют одинаковый SHA-256 активности; контроль: 0 спайков.
- Телеметрия со стимулом: около 36,6 КБ gzip; контроль: около 20,3 КБ.
- Самый первый успешный запуск до ограничения потоков/прогрева: 14.46 s wall,
  3.99 s CPU, 141.69 МиБ RSS. Это отдельное измерение, не медиана.

GitHub Actions представляется подходящим Python worker для коротких пакетных запусков;
на Linux runner измерения пока не проводились. По [правилам GitHub](https://docs.github.com/en/actions/concepts/billing-and-usage)
стандартные runner публичных репозиториев бесплатны, приватные имеют квоту. Установку
и запуск workflow, хранение артефактов и частоту нужно отдельно измерить перед включением.

Текущий Brian2/Python пакет не запускается непосредственно в Deno Supabase Edge Functions.
По [лимитам Supabase](https://supabase.com/docs/guides/functions/limits) Edge имеет 256 MB
памяти, 2 s CPU/request и 150 s wall на Free. Эти лимиты нельзя сопоставлять с нашим
macOS benchmark как гарантию работы. Для следующей фазы разумно использовать Edge как
короткий диспетчер, GitHub Actions как worker, Supabase Storage для JSON.gz и PostgreSQL
для метаданных запусков. Это рекомендация; интеграции и инфраструктура сейчас не созданы.

## Воспроизведение

Из корня репозитория, с установленным **Python 3.11**:

```bash
python3.11 -m venv .venv/neural
.venv/neural/bin/python -m pip install -r requirements.txt -r requirements-neural.txt
.venv/neural/bin/python -m pytest -q --tb=short --disable-warnings
.venv/neural/bin/python -m src.neural.experiment --output data/neural/runs/demo.json.gz
.venv/neural/bin/python -m src.neural.experiment --control --output data/neural/runs/control.json.gz
.venv/neural/bin/python -m src.neural.benchmark --output-dir data/neural/runs/new-benchmark
```

В этом рабочем каталоге совместимая среда уже находится в `.venv/neural`.
Выбирайте новые пути результатов: существующие файлы/benchmark-каталоги не перезаписываются.
CLI поддерживает выбор `--stimulus-type LC4|LPLC2|both`, `--side left|right|both`,
`--drive-mv`, `--duration-ms`, `--dt-ms`; библиотечный интерфейс принимает `Parameters`
и явные stimulus/readout IDs. Численные параметры проверяются до запуска.

Для самостоятельного повторного выделения из публичных источников:

```bash
.venv/neural/bin/python -m src.neural.ingest --output data/neural/cache/rebuilt
.venv/neural/bin/python -m src.neural.audit
# После наполнения cache можно исключить сеть полностью:
.venv/neural/bin/python -m src.neural.ingest --offline --output data/neural/cache/rebuilt-offline
```

Доступ к данным не заблокирован. Оставшиеся ограничения — неопределённая физиология,
знаки GLU/модуляторов, отсутствующие электрические синапсы/VNC и границы фрагмента.
Рекомендуемый следующий шаг: проверить ответы GF и чувствительность к фиксированным
параметрам по опубликованной электрофизиологии; отдельно подтвердить показатели на
изолированном Linux Actions runner. После этого можно проектировать Storage/observatory
и диспетчеризацию, не смешивая её с доказательством биологической достоверности.
