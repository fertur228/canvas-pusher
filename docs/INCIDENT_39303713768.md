## Confirmed defect and correction

The reproducible code defect is loss of operational failure evidence. The focused
correction adds structured diagnostics for Canvas requests/scopes, snapshot
ingestion, grade persistence, verified synchronization, and each Supabase RPC.
Records include the stage, error class/category, HTTP status when retained by the
client, retry count, GitHub run ID, elapsed milliseconds, and a validated database
error code when available. The heartbeat retains the first failed stage/category.
A per-run scanner summary records request/status counts and rate-budget minimum.

No exception strings, stack traces, URLs, request arguments, API response bodies,
account/chat IDs, tokens, titles, names, or grades are logged. Canvas GET retries
remain bounded to three attempts with existing backoff/timeouts. No database write,
outbox claim, or Telegram delivery gained a blind retry. No migration is required.

Twelve regression cases cover the confirmed silent-error paths, partial scope
failure, exhausted timeout retries, HTTP 401/429/503, PostgreSQL error metadata,
PostgREST non-JSON errors, secret redaction, and failure heartbeat/sync semantics.
The initial eight cases failed against production code before the correction.
Timeout/HTTP fixtures test diagnostic behavior; they do not claim to reproduce
the unobserved historical Canvas response.

Mandatory creation notifications, silent initialization, transactional outbox,
24/12/6/3/1-hour reminders, submission/deadline handling, and the scientific model
are unchanged. The production scheduler remains active during investigation.

## Deployment verification

Deployment and post-merge clock evidence are recorded in the incident PR and final
release report. A successful API dispatch alone is not recovery proof: require the
scanner step, verified snapshot, heartbeat, and unchanged healthy outbox for two
successive real clock ticks on the corrected commit.

Rollback: revert the focused diagnostic commit through a reviewed PR. For an actual
data-safety incident, set repository variable `CANVAS_WORKER_ENABLED=false` and,
if necessary, disable only `flymind-canvas-timer` using `cron.alter_job` with
`active := false`. Do not reset snapshots, outbox jobs, reminder markers, identities,
or credentials. The independent stale-heartbeat watchdog can remain active.
